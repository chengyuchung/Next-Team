# 温度趋势预测功能说明

## 功能概述

温度趋势预测是一个**主动预警**功能，通过监测各分区温度的变化率（升温速度），在温度**即将**突破阈值前提前触发状态升级，为操作人员争取干预时间，防止热失控等危险情况发生。

---

## 工作原理

### 1. 变化率计算

每个分区（zone 0~3）独立跟踪温度变化：

- **采样频率**：`app_task` 每 20ms 调用一次状态机，DS18B20 每次都重新采集（约 800ms 完成 4 路）
- **瞬时斜率**：`rate = (当前温度 - 上次温度) / 时间差`，单位为 **0.01°C/s**
- **EMA 平滑**：使用指数移动平均（α=0.3）过滤噪声：
  ```
  filtered_rate = 0.3 × new_rate + 0.7 × old_rate
  ```
- **异常保护**：
  - 时间差 < 100ms 或 > 5s：跳过更新（避免 guard 模式长睡眠后的突变）
  - 温度无变化：不更新斜率（保留上次值）
  - 至少需要 2 个有效样本才启用预测

### 2. 趋势预测

对每个分区，状态机会计算"预测温度"：

```c
predicted_temp = current_temp + (rate × horizon_seconds)
```

- `horizon_seconds`：预测时间窗口（默认 15 秒）
- `rate`：当前平滑后的变化率

### 3. 提前触发条件

只有同时满足以下条件，才会触发预测升级：

1. **预测功能已开启**：`g_temp_prediction_enable = 1`
2. **斜率足够陡**：`rate ≥ g_temp_prediction_min_rate`（默认 10，即 0.1°C/s）
3. **预测温度超阈值**：
   - 预测温度 ≥ 危险阈值（33.0°C）→ 提前进入 **DANGER**
   - 预测温度 ≥ 高温阈值（27.0°C）→ 提前进入 **HIGH_TEMP**
4. **当前实际温度尚未达到该阈值**（否则就不是"预测"，而是实际触发）

### 4. 只加速升级，不干预降级

- **升级路径**：NORMAL → HIGH_TEMP → DANGER，预测可以加速这个过程
- **降级路径**：保持原有的逐级回落 + 连续确认机制，预测不干预
- **低温状态**：LOW_TEMP 是"变冷"的方向，预测不处理（只关心变热风险）

## 配置参数

### 全局变量（可通过 CAN 运行时修改）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `g_temp_prediction_enable` | `uint8_t` | `1` | 使能开关：1=开启，0=关闭 |
| `g_temp_prediction_horizon_s` | `uint8_t` | `15` | 预测时间窗口（秒），建议 10~30s |
| `g_temp_prediction_min_rate` | `uint16_t` | `10` | 最小触发斜率，单位 0.01°C/s（10 表示 0.1°C/s） |

### 参数调优建议

**场景 1：电池包快速升温（热失控初期）**
- `horizon_s = 10`：短窗口，快速响应
- `min_rate = 50`：斜率阈值 0.5°C/s，只捕获剧烈升温

**场景 2：环境温度缓慢上升**
- `horizon_s = 30`：长窗口，提前量更大
- `min_rate = 5`：斜率阈值 0.05°C/s，捕获缓慢趋势

**场景 3：关闭预测功能**
- `enable = 0`

## 状态输出（可通过 CAN 查询）

在 `system_state_status_t` 结构体中新增以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `predictive_alarm` | `uint8_t` | 全局预测告警标志：任一分区触发预测则为 1 |
| `zone_predictive[4]` | `uint8_t[4]` | 各分区预测标志：1=该分区触发预测升级 |
| `zone_temp_rate[4]` | `int16_t[4]` | 各分区温度变化率，单位 0.01°C/s，符号表示升降 |

### 示例读取

```c
system_state_status_t status;
system_state_get_status(&status);

if(status.predictive_alarm != 0U) {
    // 至少有一个分区触发了预测告警
    for(uint8_t i = 0; i < 4; i++) {
        if(status.zone_predictive[i] != 0U) {
            // 分区 i 正在快速升温，已提前升级状态
            int16_t rate = status.zone_temp_rate[i];  // 例如 rate=150 表示 1.5°C/s
        }
    }
}
```

## 典型场景演示

### 场景 A：正常缓慢升温（预测不触发）

```
时间      分区0温度    变化率        预测温度（15s后）   状态
00:00     25.0°C      0.05°C/s     25.75°C            NORMAL
00:01     25.1°C      0.06°C/s     26.0°C             NORMAL
00:02     25.2°C      0.05°C/s     26.0°C             NORMAL
...       (缓慢上升，斜率 < 0.1°C/s，预测不触发)
```

**结果**：温度最终达到 27°C 时才进入 HIGH_TEMP（传统阈值触发）

---

### 场景 B：快速升温（预测提前触发）

```
时间      分区0温度    变化率        预测温度（15s后）   状态          触发原因
00:00     24.0°C      0.0°C/s      24.0°C             NORMAL        -
00:01     24.8°C      0.8°C/s      36.8°C             DANGER ⚠️     预测触发
                                   ^^^^^^ ≥ 33°C
```

**结果**：
- 实际温度才 24.8°C，距离危险阈值（33°C）还有 8°C
- 但以 0.8°C/s 的速度，15 秒后会达到 36.8°C
- **提前 15 秒进入 DANGER 状态**，风扇/水泵/泄压阀全开，蜂鸣器响起
- `status.predictive_alarm = 1`，`status.zone_predictive[0] = 1`

---

### 场景 C：突发升温后稳定（预测恢复）

```
时间      分区0温度    变化率        预测温度（15s后）   状态          说明
00:00     25.0°C      1.2°C/s      43.0°C             DANGER        预测触发
00:15     30.0°C      0.1°C/s      31.5°C             DANGER        实际到达危险区
00:30     30.5°C      0.05°C/s     30.75°C            HIGH_TEMP     逐级降级
                     ^^^ < 0.1°C/s（预测不再触发）
```

**结果**：
- 初期快速升温触发预测进入 DANGER
- 温度稳定后，斜率降到 0.05°C/s（< 0.1°C/s），预测不再触发
- 实际温度降到 < 33°C 后，经过 2 次确认（`g_fallback_confirm_count`）逐级回落到 HIGH_TEMP

## 调试与验证

### 1. 通过 CAN 查询实时状态

在上位机发送查询命令（ID=0x188, Byte1=0x02 系统状态）：

```
响应帧：
Byte0 = 0x20 (MCU)
Byte1 = 0x02
Byte2 = 当前状态（4=DANGER）
Byte3 = predictive_alarm（1=预测触发）
Byte4~7 = zone_predictive[0~3]（每字节 1 位）
```

### 2. 通过调试器观察内部变量

断点设置在 `system_state_task()` 第 700 行（分区循环内）：

```c
(gdb) p s_zone_temp_rate[0]
$1 = 150  // 表示 1.5°C/s

(gdb) p s_status.zone_predictive[0]
$2 = 1    // 分区 0 触发预测

(gdb) p s_status.predictive_alarm
$3 = 1    // 全局预测告警
```

### 3. 手动制造快速升温（测试用）

在 `app_tasks.c` 的 `system_state_update_input()` 中临时注入斜率：

```c
// 临时测试代码（不要提交到生产）
static uint32_t test_counter = 0;
if(test_counter < 100) {
    input.zone_temperature_tenths[0] = 240 + (test_counter * 8);  // 从 24°C 以 0.8°C/s 上升
    test_counter++;
}
```

预期：约 1 秒后 `predictive_alarm` 置位，状态跳到 DANGER。

## 与现有功能的兼容性

### 1. 气体/压力告警

- 气体告警 → 4 个分区**强制**进入 DANGER（预测不干预）
- 压力告警 → 4 个分区**至少**进入 HIGH_TEMP（预测不干预）

### 2. 手动模式

- 手动模式下状态机不接管执行器，但**预测仍然计算**
- `predictive_alarm` 仍会置位，只是不驱动风扇/水泵

### 3. Guard 模式

- Guard 模式的巡检周期是 15s 睡眠 + 5s 巡检
- 睡眠时 `dt > 5s`，代码会**跳过**该次变化率更新，避免误判
- 巡检期间正常计算斜率

## 常见问题

### Q1：为什么有时预测不触发？

**可能原因**：
1. `g_temp_prediction_enable = 0`（功能关闭）
2. 斜率 < 0.1°C/s（低于 `min_rate` 阈值）
3. 时间差异常（< 100ms 或 > 5s）
4. 历史样本不足（至少需要 2 个有效样本）

### Q2：预测温度会不会误报？

**防误报机制**：
1. **EMA 平滑**：α=0.3，单次噪声只影响 30%
2. **最小斜率阈值**：过滤 0.1°C/s 以下的缓慢抖动
3. **时间窗口限制**：只看 15 秒内的趋势，不会对超长期趋势过敏

### Q3：如何调整灵敏度？

**更灵敏**（捕获更多早期信号）：
- 增大 `horizon_s`（例如 30s）
- 减小 `min_rate`（例如 5，即 0.05°C/s）

**更保守**（减少误报）：
- 减小 `horizon_s`（例如 10s）
- 增大 `min_rate`（例如 20，即 0.2°C/s）

### Q4：预测触发后如何恢复？

预测只**加速升级**，不影响降级路径：

1. 温度稳定后，斜率降到 < 0.1°C/s，预测自动停止触发
2. 实际温度降到阈值以下，经过 `g_fallback_confirm_count` 次确认（默认 2 次）
3. 状态逐级回落：DANGER → HIGH_TEMP → NORMAL

## 下一步：CAN 配置命令扩展（可选）

如果需要通过上位机动态调整预测参数，可以在 `can.c` 中添加配置命令：

```c
// ID=0x18A, Byte1 = 0x10（新增命令号）
case 0x10:  // 配置预测使能
    g_temp_prediction_enable = rx_frame.data[2];
    break;

case 0x11:  // 配置预测窗口
    g_temp_prediction_horizon_s = rx_frame.data[2];
    break;

case 0x12:  // 配置最小斜率
    g_temp_prediction_min_rate = (rx_frame.data[2] << 8) | rx_frame.data[3];
    break;
```

这样就能在运行时通过 CAN 实时调整预测行为，无需重新烧录固件。

## 总结

温度趋势预测功能通过**监测升温速度**而非仅看当前温度，实现了从"被动响应"到"主动预警"的升级。在电池包热管理、工业炉温控制等场景中，这种提前干预能力可以显著提高安全性。

关键特性：
- ✅ 提前 10~30 秒触发告警
- ✅ EMA 平滑抑制噪声
- ✅ 只加速升级，不影响降级逻辑
- ✅ 参数可运行时配置
- ✅ 状态可通过 CAN 查询

建议在实际部署前，先在台架上模拟快速升温场景（例如热风枪对准传感器），验证预测触发时机和恢复行为是否符合预期。
